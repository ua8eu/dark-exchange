# dark-exchange.com

Англоязычный интерфейс криптовалютной биржи на Next.js, React и TypeScript для GitHub и Vercel. Котировки, свечи и публичный стакан поступают от Binance. Собственные торги не исполняются; балансы и операции кабинета явно обозначены как TEST USDT. Реальные депозиты и переводы в блокчейн не поддерживаются. Вымышленное юридическое лицо и лицензии не используются.

## Локальный запуск

Нужен **Node.js 24**.

```powershell
npm.cmd ci
npm.cmd run dev
```

Откройте http://localhost:3000. В текущем проекте локальное окружение уже создано. Для нового окружения скопируйте `.env.example` в `.env.local`, установите `APP_URL=http://localhost:3000`, задайте данные администратора и оставьте `DATABASE_URL` пустым для локальной SQLite-базы.

Локальный администратор: `admin@dark-exchange.com`. Уникальный пароль находится в `ADMIN_PASSWORD` файла `.env.local`. Нажмите **Log in → Assets → Admin**, чтобы начислить тестовые средства или настроить минимум первого тестового вывода.

`.env.local`, `.data/`, ключи и результаты проверок исключены из Git. В Vercel секреты задаются в **Settings → Environment Variables**.

## GitHub → Vercel

1. Создайте GitHub-репозиторий и загрузите исходники вместе с `package-lock.json`, `vercel.json`, `.nvmrc` и `.env.example`.
2. В Vercel выберите **Add New → Project → Import Git Repository**. Framework — **Next.js**, Root Directory — корень репозитория, Node.js — **24.x**. Output Directory оставьте стандартной.
3. Подключите PostgreSQL, например **Neon через Vercel Marketplace / Storage**. Используйте pooled connection string с TLS в `DATABASE_URL`.
4. Добавьте серверные переменные из таблицы ниже. Подтвердите домен отправителя у SMTP-провайдера.
5. Выполните `npm run db:migrate` с переменными целевой базы. Команда создаёт таблицы и начального администратора, не сбрасывая существующие данные. Она не запускается автоматически во время сборки.
6. Выполните Deploy. В **Settings → Domains** добавьте `dark-exchange.com`, настройте DNS по значениям Vercel. Production `APP_URL=https://dark-exchange.com`. После изменения переменных сделайте Redeploy.

Это приложение с серверными API, а не статический экспорт. В production требуется PostgreSQL: без `DATABASE_URL` API аккаунтов вернёт ошибку настройки, вместо создания временной файловой базы.

## Переменные окружения

| Переменная | Значение / назначение |
| --- | --- |
| `APP_URL` | Production: `https://dark-exchange.com`; ссылки подтверждения и проверка Origin |
| `DATABASE_URL` | PostgreSQL pooled URL с TLS, например от Neon |
| `ADMIN_EMAIL` | Email начального администратора |
| `ADMIN_PASSWORD` | Уникальный пароль 12–128 символов при начальном создании |
| `FIRST_WITHDRAWAL_MINIMUM` | Начальный минимум первого тестового вывода; по умолчанию `1000` |
| `SMTP_HOST` | Хост почтового провайдера |
| `SMTP_PORT` | Обычно `587` с STARTTLS или `465` с TLS |
| `SMTP_SECURE` | `true` для 465; `false` для 587 с обязательным STARTTLS в production |
| `SMTP_USER` / `SMTP_PASSWORD` | Серверные данные SMTP |
| `SMTP_FROM` | Подтверждённый отправитель: `Dark Exchange Demo <no-reply@dark-exchange.com>` |
| `ALLOW_DEMO_ACCESS` | `false` на Vercel; быстрый демо-вход доступен только в development |

Все секреты — серверные переменные: не используйте для них префикс `NEXT_PUBLIC_`.

Для Preview используйте отдельную ветку/базу Neon. Оставьте Preview `APP_URL` незаданным: приложение использует адрес текущего preview из системной переменной Vercel. Либо задайте точный адрес вручную. Переменную `APP_URL=https://dark-exchange.com` включайте только для Production, иначе preview-формы будут отклонены проверкой Origin.

Локальные SQLite-аккаунты не переносятся в облако автоматически. PostgreSQL — отдельное окружение. Повторная миграция не сбрасывает существующий пароль; изменение `ADMIN_PASSWORD` в окружении его не меняет.

## Рыночные данные

Источник — [официальный публичный API Binance](https://developers.binance.com/en/docs/products/spot/faqs/market_data_only), `data-api.binance.vision`. API-ключ не требуется. Браузер использует ограниченные серверные маршруты `/api/market/*`; произвольные внешние адреса не принимаются.

Поддерживаются BTC, ETH, SOL, BNB, XRP, AVAX, LINK и DOGE в парах с USDT. Котировки обновляются автоматически; интерфейс показывает источник и свежесть. Основной график и мини-графики используют реальные публичные свечи. Стакан и недавние сделки относятся к внешнему рынку Binance, а не к исполнению сделок на этом сайте.

При сбое последняя информация помечается как задержанная. Начальные справочные значения не обозначаются актуальными; недоступная история отображается соответствующим состоянием. Доступность API зависит от региона хостинга и правил провайдера. Проверьте `/api/market/tickers` из целевого Vercel-развёртывания.

## Регистрация и кошелёк

Регистрация требует пароль 12–128 символов и одноразовое подтверждение email. Ссылка действует 24 часа. SMTP отправляет настоящие письма. Без SMTP в development доступен явно обозначенный локальный просмотр письма. В production ссылки подтверждения не раскрываются клиенту.

Начисление администратором и запись в истории выполняются одной транзакцией. Сумма операции совпадает с изменением баланса; учёт ведётся целыми центами.

Тестовый вывод принимает сумму, сеть и адрес назначения. Для первого принятого запроса действует минимум из **Assets → Admin**. Принятая сумма резервируется и вычитается из доступного тестового баланса; статус — Pending. Реальный перевод не выполняется. Дополнительный депозит или комиссия для прохождения ограничения не требуются.

## Проверки

```powershell
npm.cmd test
npm.cmd run typecheck
npm.cmd run build
```

GitHub Actions запускает `npm ci`, тесты и production-сборку на Node.js 24. Секреты для CI не требуются: PostgreSQL-логика проверяется локальным движком PGlite. Публикацией управляет интеграция Vercel с GitHub.

Тесты проверяют авторизацию, роли, одноразовые токены, SMTP-доставку через тестовый сервер, точность сумм, откат операций, первый вывод, защиту настроек и PostgreSQL. SQLite используется только для локальной разработки и тестов; PostgreSQL — для постоянных данных Vercel.

Документация: [Vercel + Neon](https://neon.com/docs/guides/vercel-overview), [Node.js на Vercel](https://vercel.com/docs/functions/runtimes/node-js/node-js-versions).
